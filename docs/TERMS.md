## 🌱 처음 시작

### 기본 말
- 🌱 **바이브코딩 (Vibe Coding)**: 코드를 직접 쓰기보다 말로 원하는 것을 설명해 AI가 만들게 하는 방식.
- 🌱 **코드 (Code)**: 컴퓨터가 알아듣는 말로 쓴 명령 글. 웹앱의 설계도이자 재료.
- 🌱 **실행 (Run)**: 코드를 작동시켜 결과 화면을 보는 것.
- 🌱 **미리보기 (Preview)**: 배포 전에 만든 화면을 먼저 확인해 보는 것.
- 🌱 **웹사이트 (Website)**: 주로 읽고 보는 인터넷 페이지.
- 🌱 **웹앱 (Web App)**: 누르고 입력하며 무언가를 하는, 앱처럼 작동하는 웹페이지.
- 🌱 **vs 웹사이트 vs 웹앱**: 보는 것 중심이면 웹사이트, 하는 것 중심이면 웹앱.
- 🌱 **노코드 (No-code)**: 코드 없이 블록을 끌어다 놓아 만드는 도구. 예: 패들렛, 구글 사이트.
- 🌱 **vs 노코드 vs 바이브코딩**: 노코드는 정해진 블록 안에서, 바이브코딩은 말로 무엇이든 코드로.
- 🌱 **템플릿 (Template)**: 미리 만들어 둔 틀. 내용만 바꿔 쓰면 됨.
- 🌱 **결과물 창 (Artifact / Canvas)**: AI가 대화 옆에 바로 보여 주는 결과 화면. 여기서 눌러 보며 확인.
- 🌱 **버전 (Version)**: 고칠 때마다 생기는 판. "v2", "어제 버전"처럼 부름.
- 🌱 **무료 한도 (Free Tier)**: 돈 안 내고 쓸 수 있는 사용량 범위. 넘으면 멈추거나 유료로 바뀜.

### 컴퓨터와 브라우저
- 🌱 **브라우저 (Browser)**: 웹페이지를 여는 프로그램. 예: 크롬, 엣지, 사파리.
- 🌱 **주소 (URL)**: 웹페이지마다 있는 고유 주소. https://로 시작.
- 🌱 **새 탭 / 새 창 (New Tab / Window)**: 지금 화면은 두고 다른 페이지를 하나 더 여는 것.
- 🌱 **시크릿 창 (Incognito Window)**: 저장된 기록·캐시 없이 처음 방문한 것처럼 여는 창. 고친 게 반영됐는지 볼 때 좋음.
- 🌱 **쿠키 (Cookie)**: 사이트가 내 브라우저에 남겨 두는 작은 기억 쪽지. 로그인 유지 등에 씀.
- 🌱 **팝업 차단 (Popup Blocker)**: 새 창이 저절로 뜨는 것을 브라우저가 막는 기능.
- 🌱 **다운로드 / 업로드 (Download / Upload)**: 인터넷에서 내 컴퓨터로 받기 / 내 컴퓨터에서 인터넷으로 올리기.
- 🌱 **압축 파일 (ZIP)**: 여러 파일을 하나로 묶은 파일. 열려면 "압축 풀기".
- 🌱 **확대·축소 (Zoom)**: Ctrl + 마우스 휠로 화면 크기 바꾸기. 배치가 깨져 보이면 100%인지 확인.
- 🌱 **자주 쓰는 단축키 (Shortcuts)**: 복사 Ctrl+C · 붙여넣기 Ctrl+V · 되돌리기 Ctrl+Z · 저장 Ctrl+S · 찾기 Ctrl+F.
- 🌱 **캡처 (Screenshot)**: 화면을 그림으로 찍기. 윈도우는 Win+Shift+S. AI에게 보여 줄 때 필수.

### AI 답변 읽기
- 🌱 **코드 블록 (Code Block)**: AI 답변 속 회색 상자. 이 안이 실제 코드라 통째로 복사해야 함.
- 🌱 **통째로 복사 (Copy All)**: 코드 블록 오른쪽 위 복사 버튼으로 빠짐없이 복사하기. 일부만 복사하면 깨짐.
- 🌱 **마크다운 (Markdown)**: #, *, - 같은 기호로 제목·굵게·목록을 표시하는 글쓰기 방식. AI 답변과 README가 이 형식.
- 🌱 **줄 번호 (Line Number)**: 코드 왼쪽 숫자. "42번째 줄"처럼 위치를 짚을 때 씀.
- 🌱 **들여쓰기 (Indentation)**: 줄 앞 빈칸. 코드의 안팎 관계를 보여 줌.
- 🌱 **괄호 짝 (Brackets)**: ( ) { } [ ]는 반드시 열고 닫는 짝이 맞아야 함. 하나만 빠져도 전체가 멈춤.
- 🌱 **따옴표 (Quotes)**: 글자는 "따옴표" 안에 넣음. 한글 입력기의 둥근 따옴표(“ ”)는 코드에서 오류가 남.
- 🌱 **대소문자 구분 (Case Sensitive)**: 코드는 Button과 button을 다른 것으로 봄.
- 🌱 **생략된 코드 (Truncated Code)**: AI가 "// 나머지는 그대로"라고 줄여 쓴 부분. 그대로 붙이면 코드가 사라짐. "전체 코드로 줘"라고 다시 요청.

### 자주 만나는 문제
- 🌱 **흰 화면 (Blank Screen)**: 아무것도 안 뜨는 상태. 대부분 코드 오류라 콘솔부터 확인.
- 🌱 **에러 (Console Error)**: 앱이 멈추거나 기능이 안 되게 만드는 문제. 꼭 고쳐야 함.
- 🌱 **경고 (Console Warning)**: 앱은 작동하지만 고치면 좋은 문제. 나중에 고쳐도 됨.
- 🌱 **vs 에러 vs 경고 (Error vs Warning)**: 에러는 멈추게 하는 문제(빨강), 경고는 작동은 하지만 고치면 좋은 문제(노랑).
- 🌱 **한글 깨짐 (Encoding / UTF-8)**: 한글이 ?나 이상한 글자로 보이는 것. 파일을 UTF-8로 저장하면 해결.
- 🌱 **그림 깨짐 (Broken Image)**: 그림 자리에 깨진 아이콘만 보이는 것. 대부분 파일 경로나 이름 오타.
- 🌱 **반영 안 됨 (Not Updated)**: 고쳤는데 그대로인 것. 저장했는지 → 강력 새로고침 → 시크릿 창 순서로 확인.
- 🌱 **멈춤 (Freeze)**: 화면이 반응하지 않는 것. 무한 반복 코드가 원인일 때가 많음.
- 🌱 **고치다 더 망가짐 (Regression)**: 하나 고쳤더니 다른 곳이 망가지는 것. 잘 될 때 버전을 저장해 두면 되돌릴 수 있음.
- 🌱 **휴대폰에서만 이상함 (Mobile Bug)**: 컴퓨터에선 괜찮은데 휴대폰에서 깨지는 것. 기기 모드로 미리 확인.

- **3D 아이콘 (3D Icon)**: 입체감과 광택이 있는 아이콘 스타일.

### 글자 스타일
애시드 그래픽 · 글리치 · 인플레이트 3D · 바우하우스 · 아르데코 · 아웃라인 · 모노스페이스 · 핸드레터링 · 미니멀
- **브루탈리즘 (Brutalism)**: 아주 굵고 큰 글자를 화면 가득 채워 거칠고 직설적으로 보여 주는 글자 스타일.
- **네오 브루탈리즘 (Neo-brutalism)**: 굵은 검은 테두리와 딱 떨어지는 그림자, 선명한 색 위에 굵은 글자를 올리는 글자 스타일.
- **스위스 스타일 (Swiss Style)**: 그리드에 맞춰 왼쪽 정렬한 깔끔한 산세리프 글자 스타일.
- **에디토리얼 (Editorial)**: 잡지 제목처럼 우아한 세리프 글자를 크게 쓰는 글자 스타일.
- **청키 (Chunky)**: 통통하고 두툼한 글자로 귀엽고 묵직한 인상을 주는 글자 스타일.
- **레트로 그루비 (Retro Groovy)**: 70년대풍 물결치는 곡선 글자와 따뜻한 색을 쓰는 글자 스타일.
- **Y2K 크롬 (Y2K Chrome)**: 2000년대 초 감성의 반짝이는 금속 질감 글자 스타일.
- **픽셀 (Pixel)**: 네모난 점으로 이루어져 옛날 게임 화면 같은 글자 스타일.
- **키네틱 (Kinetic)**: 글자가 움직이며 리듬과 강조를 만드는 글자 스타일.

### 화면 배치
히어로 · 벤토 그리드 · 스플릿 · 카드 그리드 · 그리드 레이아웃 · 사이드바 레이아웃 · 매거진 · 메이슨리 · 리스트 레이아웃 · 컬럼 레이아웃 · 대시보드 · Z 패턴 · 풀블리드
- **F 패턴 (F-Pattern)**: 글이 많은 화면에서 시선이 F자로 훑어 내려가는 것을 고려한 배치.
- **센터 정렬 (Centered Layout)**: 내용을 화면 가운데 좁은 폭으로 모아 읽기 편하게 하는 배치.

### 꾸밈 속성
- **안쪽 여백 (Padding)**: 상자 테두리와 안의 내용 사이 간격.
- **바깥 여백 (Margin)**: 상자와 주변 다른 요소 사이 간격.
- **vs 패딩 vs 마진**: 패딩은 상자 안쪽, 마진은 상자 바깥쪽 여백.
- **간격 (Gap)**: 나란히 놓인 요소들 사이의 일정한 거리.
- **모서리 둥글기 (Border Radius)**: 상자 모서리를 둥글게 깎는 정도. 끝까지 둥글면 알약 모양.
- **테두리 (Border)**: 상자 가장자리 선. 두께·색·점선 여부를 정함.
- **그림자 (Drop Shadow)**: 요소 아래에 그림자를 깔아 떠 있는 느낌을 줌.
- **투명도 (Opacity)**: 요소가 비쳐 보이는 정도. 0이면 안 보이고 1이면 불투명.
- **블러 (Blur)**: 요소나 뒤 배경을 흐리게 하는 효과. 유리 느낌의 핵심.
- **그라데이션 (Gradient)**: 한 색에서 다른 색으로 자연스럽게 바뀌는 채색.
- **구분선 (Divider)**: 내용 사이를 나누는 가는 선.

### 색과 글자
- **주요색 (Primary Color)**: 사이트를 대표하고 버튼·강조에 쓰는 색.
- **강조색 (Accent Color)**: 눈에 띄어야 할 곳에만 조금 쓰는 색.
- **색 팔레트 (Color Palette)**: 사이트에서 쓰는 색들을 정해 둔 묶음.
- 🌱 **색 코드 (HEX Code)**: #0095FF처럼 색을 숫자로 적은 것. AI에게 색을 정확히 말할 때 씀.
- **대비 (Contrast)**: 글자와 배경의 밝기 차이. 낮으면 읽기 어려움.
- **글자 굵기 (Font Weight)**: 가늘게~굵게 정도. 숫자(400 보통, 700 굵게)로 말하기도 함.
- 🌱 **글자 크기 (Font Size)**: 글자의 크기. px로 말함. 본문은 보통 16px 이상.
- **줄 간격 (Line Height)**: 줄과 줄 사이 거리.
- **자간 (Letter Spacing)**: 글자와 글자 사이 거리.
- **말줄임 (Text Truncation / Ellipsis)**: 글이 길면 뒤를 "…"로 줄여 보여 주기.
- **웹폰트 (Web Font)**: 인터넷에서 불러와 쓰는 글꼴. 예: LevelUp, Pretendard.

### 그림과 파일 형식
- **PNG**: 투명 배경이 되는 그림 파일. 아이콘·캐릭터에 적합.
- **JPG**: 사진에 맞는 가벼운 그림 파일. 투명 배경은 안 됨.
- **SVG**: 선과 도형으로 저장해 아무리 키워도 깨지지 않는 그림 파일.
- **WebP**: 화질은 비슷하고 용량이 작은 웹용 그림 파일.
- **벡터 (Vector)**: 선과 도형 정보로 저장한 그림. 아무리 키워도 선명함.
- **비트맵 (Bitmap)**: 작은 점(픽셀)을 모아 만든 그림. 크게 키우면 흐려지고 계단처럼 보임.
- **vs 벡터 vs 비트맵**: 벡터는 선·도형 정보라 확대해도 선명, 비트맵은 점(픽셀)이라 확대하면 흐려짐.
- **투명 배경 (Transparent Background)**: 그림 뒤가 비어 있어 어떤 배경 위에도 자연스럽게 놓이는 것.
- **해상도 (Resolution)**: 그림을 이루는 점의 개수. 높을수록 선명하고 용량이 큼.
- **비율 (Aspect Ratio)**: 가로와 세로의 비. 예: 16:9, 4:3, 1:1.
- **잘라 맞추기 (Cover)**: 칸을 빈틈없이 꽉 채우려고 그림 가장자리를 잘라 내는 방식.
- **전체 보이기 (Contain)**: 그림이 잘리지 않고 다 보이게 넣고, 남는 곳은 여백으로 두는 방식.
- **vs 잘라 맞추기 vs 전체 보이기 (Cover vs Contain)**: 칸을 꽉 채우려고 그림을 자를지, 그림 전체가 보이게 여백을 둘지.
- **에셋 (Asset)**: 앱에 쓰이는 그림·소리·글꼴 같은 재료 파일 묶음.
- **스프라이트 (Sprite)**: 움직이는 그림 조각들을 한 장에 모은 것.
- **이모지 (Emoji)**: 글자처럼 입력되는 그림 문자. 기기마다 모양이 다름.

- **순서 맞추기 (Ordering)**: 섞인 카드를 올바른 순서로 늘어놓기.
- **빈칸 채우기 (Fill in the Blank)**: 문장 속 빈칸에 알맞은 말을 넣거나 골라 넣기.
- **플래시카드 (Flashcard)**: 앞면은 문제, 뒤집으면 답이 나오는 카드.
- **정답·오답 피드백 (Answer Feedback)**: 맞히면 동그라미·소리·칭찬, 틀리면 부드러운 안내와 다시 하기.
- **힌트 (Hint)**: 막힐 때 누르면 단계적으로 도움을 주는 버튼.
- **다시 하기 (Retry)**: 틀린 문제나 활동을 처음부터 다시 시작하는 기능.
- **결과 화면 (Result Screen)**: 맞힌 개수, 칭찬, 다음 활동을 보여 주는 마지막 화면.

### 게임 장치
- **점수 (Score)**: 맞히거나 해낸 만큼 올라가는 숫자.
- **타이머 (Timer)**: 남은 시간을 보여 주는 표시. 숫자, 줄어드는 막대, 모래시계 등.
- **기회 (Lives / Hearts)**: 틀릴 때마다 하나씩 줄어드는 하트.
- **레벨·스테이지 맵 (Level Map)**: 길 위의 점을 하나씩 깨며 앞으로 나아가는 진행 지도.
- **보상 (Reward)**: 스티커·별·배지처럼 해냈을 때 받는 것.
- **리더보드 (Leaderboard)**: 점수 순위를 보여 주는 표. 수업에서는 팀 점수로 쓰기도 함.
- **랜덤 뽑기 (Random Picker / Spinner Wheel)**: 룰렛을 돌리거나 카드를 섞어 무작위로 고르기.
- **주사위 (Dice Roll)**: 굴려서 나온 숫자만큼 움직이는 장치.
- **효과음 (Sound Effect)**: 버튼·정답·오답에 붙는 짧은 소리. 끄기 설정도 함께.
- **게이미피케이션 (Gamification)**: 점수·레벨·보상 같은 게임 요소를 학습에 더하는 방법.

### 만들기 활동
- **캔버스 그리기 (Drawing Canvas)**: 손가락이나 펜으로 자유롭게 그리는 판.
- **색칠하기 (Coloring)**: 선 그림의 칸을 눌러 색을 채우기.
- **스티커 붙이기 (Sticker Placement)**: 그림 조각을 끌어다 배경 위에 배치하기.
- **꾸미기 (Customization / Dress-up)**: 얼굴·옷·소품을 골라 바꿔 입히기.
- **결과물 저장 (Save as Image)**: 완성한 화면을 그림 파일로 내려받기.
- **인쇄하기 (Print)**: 완성물을 종이로 뽑기. 인쇄용 화면을 따로 맞춤.
- **갤러리 공유 (Shared Gallery)**: 친구들 결과물을 한곳에 모아 함께 보기.

## 🧠 UX 원칙
> 카드 애니메이션: 왼쪽 아쉬운 예 → 오른쪽 좋은 예

### 보기 쉽게
- **시각적 위계 (Visual Hierarchy)**: 중요한 것일수록 크고 진하게 해서 보는 순서를 정해 주기.
- **여백 (White Space)**: 요소 사이 빈 공간. 넉넉하면 덜 복잡해 보임.
- **근접성 (Proximity)**: 관련 있는 것끼리 가까이 두면 한 묶음으로 보이는 원리.
- **정렬 (Alignment)**: 요소들의 가장자리나 가운데를 맞춰 정돈돼 보이게 하기.
- **일관성 (Consistency)**: 같은 기능은 어디서나 같은 모양·위치·이름으로.
- **가독성 (Readability)**: 글자 크기·줄 간격·대비를 맞춰 읽기 쉽게 하기.
- **인지 부하 (Cognitive Load)**: 한 번에 생각해야 할 양. 줄일수록 쉽게 씀.
- **점진적 공개 (Progressive Disclosure)**: 처음엔 꼭 필요한 것만 보이고, 더 필요하면 펼쳐 보기.

### 쓰기 쉽게
- **어포던스 (Affordance)**: 생김새만 보고 "눌러도 되겠다"를 알 수 있게 하는 것.
- **피드백 (Feedback)**: 누르거나 입력하면 바로 반응을 보여 주기.
- **터치 영역 (Touch Target)**: 손가락으로 누를 수 있는 범위. 최소 44px 정도로 넉넉하게.
- **피츠의 법칙 (Fitts's Law)**: 크고 가까운 버튼일수록 빠르고 정확하게 누름.
- **힉의 법칙 (Hick's Law)**: 고를 게 많을수록 결정이 오래 걸림. 선택지는 적게.
- **기본값 (Default Value)**: 처음부터 골라져 있는 값. 대부분이 고를 값을 기본으로.
- **오류 예방 (Error Prevention)**: 실수하기 전에 막기. 예: 지우기 전 확인, 잘못된 입력 막기.
- **되돌릴 수 있음 (Reversibility)**: 실수해도 실행 취소로 돌아갈 수 있게 하기.
- **다크 패턴 (Dark Pattern)**: 사용자를 속여 원치 않는 선택을 하게 만드는 나쁜 설계.

### 사용자 이해하기
- **사용성 (Usability)**: 목표를 얼마나 쉽고 빠르고 실수 없이 이룰 수 있는지.
- **페르소나 (Persona)**: 대표 사용자를 한 사람처럼 정리한 가상 인물.
- **사용자 여정 (User Journey)**: 사용자가 처음 알게 되는 순간부터 다 쓸 때까지의 경험 흐름.
- **정보 구조 (Information Architecture)**: 메뉴와 내용을 어떻게 나누고 묶을지 정한 지도.
- **사용성 테스트 (Usability Test)**: 실제 사용자가 써 보는 모습을 보고 문제를 찾기.
- **A/B 테스트 (A/B Test)**: 두 가지 안을 나눠 보여 주고 어느 쪽이 나은지 비교하기.
- **쉬운 말 (Plain Language)**: 어려운 낱말 대신 짧고 쉬운 말로 안내하기. 특수교육 앱에서 특히 중요.
- **보편적 설계 (Universal Design)**: 처음부터 누구나 쓸 수 있게 만드는 설계.

## 📐 화면 크기

### 반응형과 위치
- **반응형 (Responsive Design)**: 컴퓨터·태블릿·휴대폰 화면 크기에 맞춰 배치가 바뀌는 것.
- **브레이크포인트 (Breakpoint)**: 배치가 바뀌는 화면 너비 기준. 예: 768px부터 태블릿.
- **뷰포트 (Viewport)**: 지금 브라우저에서 실제로 보이는 화면 영역.
- 🌱 **픽셀 (px)**: 화면 크기를 재는 가장 작은 점 단위. "버튼 높이 48px"처럼 씀.
- **모바일 퍼스트 (Mobile First)**: 휴대폰 화면부터 먼저 설계하고 큰 화면으로 넓히는 방식.
- **가로·세로 모드 (Landscape / Portrait)**: 기기를 눕혔을 때와 세웠을 때의 화면 방향.
- **고정 (Fixed)**: 스크롤해도 화면의 같은 자리에 붙어 있는 요소.
- **스티키 (Sticky)**: 평소엔 같이 스크롤되다가 특정 위치에 닿으면 붙어 있는 요소.
- **vs 고정 vs 스티키**
- **겹침 순서 (z-index)**: 요소가 겹칠 때 무엇이 위에 올라올지 정하는 순서.
- **넘침 (Overflow)**: 내용이 상자보다 클 때 잘라낼지, 스크롤할지 정하는 것.
- **가운데 정렬 (Center Alignment)**: 요소를 가로·세로 가운데에 놓기.
- **전체화면 (Fullscreen)**: 브라우저 메뉴까지 숨기고 화면 전체를 쓰는 모드.
- **안전 영역 (Safe Area)**: 노치·홈 인디케이터에 가리지 않는 휴대폰 화면 안쪽 영역.

### 기기와 브라우저
- **크로스 브라우저 (Cross-browser)**: 크롬·사파리·엣지 어디서나 똑같이 보이고 작동하는지.
- **기기 모드 (Device Mode)**: 개발자 도구에서 휴대폰·태블릿 화면 크기로 미리 보기.
- **전자칠판·큰 화면 (Large Touch Display)**: 교실 큰 화면용. 버튼과 글자를 크게, 멀리서도 보이게.
- **홈 화면에 추가 (Add to Home Screen / PWA)**: 웹앱을 앱처럼 아이콘으로 깔아 쓰는 기능.
- **오프라인 사용 (Offline Support)**: 인터넷이 끊겨도 일부 기능을 쓸 수 있게 하는 것.
- **인쇄 스타일 (Print Style)**: 인쇄할 때만 버튼을 숨기고 A4에 맞추는 꾸밈.
- **화면 꺼짐 방지 (Wake Lock)**: 활동하는 동안 화면이 꺼지지 않게 하기.

## 🛠 만들고 배포하기

### 코드 기본
- **HTML · CSS · 자바스크립트 (HTML / CSS / JavaScript)**: 웹페이지의 뼈대, 꾸밈, 움직임을 맡는 세 가지 언어.
- **프론트엔드 (Frontend)**: 사용자가 보고 만지는 화면 쪽.
- **백엔드 (Backend)**: 화면 뒤에서 데이터를 저장·처리하는 서버 쪽.
- **vs 프론트엔드 vs 백엔드**
- **컴포넌트 (Component)**: 버튼·카드처럼 여러 번 다시 쓰는 화면 조각.
- **상태 (State)**: 지금 켜졌는지, 몇 개 골랐는지처럼 화면이 기억하는 값.
- **변수 (Variable)**: 값을 담아 두는 이름 붙은 상자. 예: 점수 = 0.
- **함수 (Function)**: 여러 번 쓰는 동작을 묶어 이름 붙인 것. 예: 정답확인().
- **이벤트 (Event)**: 클릭·입력·스크롤처럼 사용자가 한 행동. "버튼 클릭 이벤트".
- **조건문 (If Statement)**: "만약 ~이면 ~하고, 아니면 ~해"처럼 상황에 따라 다르게 동작.
- **반복문 (Loop)**: 같은 일을 여러 번 되풀이하는 코드.
- **배열 (Array)**: 여러 값을 순서대로 담은 목록. 예: [사과, 배, 포도].
- **JSON**: 데이터를 이름과 값의 짝으로 적는 형식.
- **주석 (Comment)**: 코드 안에 사람이 읽으라고 적는 메모. 실행되지 않음.
- **비동기 (Async)**: 데이터를 기다리는 동안 화면이 멈추지 않게 하는 처리 방식.
- **랜덤 (Random)**: 무작위 값을 뽑는 기능. 문제 섞기에 씀.
- **프레임워크 (Framework)**: 앱을 만드는 틀과 규칙을 통째로 제공하는 도구. 예: 리액트, Next.js.
- **라이브러리 (Library)**: 필요한 기능만 가져다 쓰는 코드 묶음. 예: 아이콘, 차트.
- **vs 프레임워크 vs 라이브러리**
- **단일 HTML 파일 (Single HTML File)**: 화면·꾸밈·기능을 파일 하나에 모두 넣은 간단한 웹앱.
- **리액트 프로젝트 (React Project)**: 화면·기능을 여러 파일(컴포넌트)로 나눠 만드는 리액트 앱. 화면과 기능이 많을 때 알맞음.
- 🌱 **vs 단일 HTML vs 리액트 프로젝트**: 간단하면 파일 하나, 화면·기능이 많으면 여러 파일로 나눈 리액트.
- **패키지 설치 (npm install)**: 다른 사람이 만든 코드 묶음을 내 프로젝트에 내려받는 것.

### 파일과 도구
- **폴더 구조 (Folder Structure)**: 프로젝트 파일을 어떤 폴더에 나눠 두었는지.
- **경로 (Path)**: 파일이 있는 위치 주소. 예: images/cat.png.
- **확장자 (File Extension)**: 파일 이름 끝 .html .css .js .png처럼 종류를 알려 주는 부분.
- 🌱 **파일 이름 규칙 (File Naming)**: 영어 소문자·숫자·하이픈(-)만 쓰기. 한글·띄어쓰기는 오류의 원인.
- **index.html**: 사이트에 들어오면 가장 먼저 열리는 기본 파일.
- **README**: 프로젝트 설명서 파일. 무엇이고 어떻게 쓰는지 적음.
- **코드 편집기 (Code Editor)**: 코드를 쓰고 고치는 프로그램. 예: VS Code.
- **터미널 (Terminal)**: 글자 명령어로 컴퓨터에 일을 시키는 창.
- **개발자 도구 (DevTools)**: 브라우저에서 F12로 여는 점검 도구. 콘솔·기기 모드가 여기 있음.
- **확장 프로그램 (Extension)**: 편집기나 브라우저에 기능을 더하는 추가 프로그램.

### 데이터와 저장
- **데이터베이스 (Database)**: 정보를 표처럼 쌓아 두고 꺼내 쓰는 저장소. 예: Supabase.
- **CRUD**: 데이터의 만들기·읽기·고치기·지우기 네 가지 기본 동작.
- **테이블·행·열 (Table / Row / Column)**: 데이터베이스의 표, 가로줄(한 건), 세로줄(항목).
- **스키마 (Schema)**: 표에 어떤 칸이 있고 어떤 종류 값이 들어가는지 정한 설계도.
- **로컬 스토리지 (Local Storage)**: 브라우저 안에 작은 데이터를 저장하는 곳. 다른 기기와는 공유 안 됨.
- 🌱 **vs 로컬 스토리지 vs 데이터베이스**: 내 브라우저에만 남기기 vs 어느 기기에서나 같이 보기.
- **스토리지 (Storage)**: 사진·파일을 올려 두는 저장 공간. 데이터베이스와 따로 있음.
- **스프레드시트 DB (Spreadsheet as Database)**: 구글 시트를 데이터베이스처럼 쓰는 방법. 앱스 스크립트로 연결.
- **CSV**: 쉼표로 칸을 나눈 표 파일. 엑셀·시트와 쉽게 주고받음.
- **API**: 다른 서비스와 데이터를 주고받는 창구.
- **API 키 (API Key)**: API를 쓸 수 있게 해 주는 비밀 열쇠. 화면 코드에 그대로 넣으면 안 됨.
- **환경 변수 (Environment Variable)**: API 키 같은 비밀 값을 코드 밖에 따로 보관하는 방법.
- **로그인·인증 (Authentication)**: 사용자가 누구인지 확인하는 기능.
- **실시간 (Realtime)**: 다른 사람이 바꾼 내용이 새로고침 없이 바로 보이는 것.
- **백업 (Backup)**: 데이터를 따로 복사해 두기.
- **동기화 (Sync)**: 컴퓨터와 휴대폰처럼 여러 기기의 데이터를 같게 맞추기.

### 보안과 개인정보
- **개인정보 (Personal Information)**: 이름·얼굴·연락처처럼 누구인지 알 수 있는 정보. 학생 정보는 꼭 필요한 만큼만.
- **익명화 (Anonymization)**: 실명 대신 번호나 별명으로 바꿔 누구인지 모르게 하기.
- **HTTPS**: 주소창 자물쇠 표시. 주고받는 정보가 암호화됨.
- **접근 권한 (Access Control)**: 누가 보고, 누가 고칠 수 있는지 정하는 것. 예: 교사만 삭제.
- **행 수준 보안 (Row Level Security, RLS)**: 데이터베이스에서 각자 자기 데이터만 보게 막는 규칙. Supabase에서 켜야 함.
- **비밀 키 노출 (Secret Leak)**: API 키를 코드나 공개 저장소에 올려 남이 쓸 수 있게 되는 사고.
- **공개 저장소 (Public Repository)**: 누구나 코드를 볼 수 있는 저장소. 비밀 키나 개인정보를 넣으면 안 됨.
- **비공개 저장소 (Private Repository)**: 나와 초대한 사람만 볼 수 있는 저장소.
- **vs 공개 vs 비공개 저장소 (Public vs Private Repository)**: 누구나 코드를 볼 수 있는지 여부.

### 문제 해결
- **콘솔 (Console)**: 브라우저 개발자 도구에서 오류 메시지를 확인하는 창. F12로 열기.
- **에러 메시지 (Error Message)**: 무엇이 잘못됐는지 알려 주는 글. 통째로 복사해 AI에게 주면 좋음.
- **버그 (Bug)**: 의도와 다르게 작동하는 문제.
- **디버깅 (Debugging)**: 버그의 원인을 찾아 고치는 과정.
- **캐시 (Cache)**: 빠르게 열려고 저장해 둔 예전 파일. 고쳤는데 안 바뀌면 캐시 때문일 수 있음.
- **강력 새로고침 (Hard Refresh)**: 캐시를 무시하고 새로 불러오기 (Ctrl+Shift+R).
- **로컬 서버 (localhost)**: 배포 전 내 컴퓨터에서만 미리 열어 보는 주소.

### 버전 관리
- 🌱 **깃허브 (GitHub)**: 코드를 저장하고 바뀐 기록을 남기며 다른 사람과 함께 작업하는 사이트.
- **저장소 (Repository)**: 프로젝트 파일과 바뀐 기록을 모아 둔 곳.
- **커밋 (Commit)**: 지금까지 바꾼 내용을 기록으로 저장하기.
- **푸시 (Push)**: 내 컴퓨터의 커밋을 GitHub에 올리기.
- **풀 (Pull)**: GitHub의 최신 내용을 내 컴퓨터로 가져오기.
- **클론 (Clone)**: 저장소 전체를 내 컴퓨터로 복사해 오기.
- **포크 (Fork)**: 다른 사람 저장소를 내 계정으로 복사해 따로 고치기.
- **브랜치 (Branch)**: 원본은 두고 따로 갈라서 실험하는 작업 줄기.
- **머지 (Merge)**: 갈라진 작업(브랜치)을 원본에 합치기.
- **풀 리퀘스트 (Pull Request, PR)**: "내가 고친 것 합쳐 주세요" 하고 검토를 요청하기.
- **충돌 (Merge Conflict)**: 두 사람이 같은 곳을 다르게 고쳐서 자동으로 합칠 수 없는 상황.
- **이슈 (Issue)**: 고칠 점이나 할 일을 적어 두는 게시글.

### 배포와 공유
- **배포 (Deploy)**: 만든 웹앱을 인터넷에 올려 누구나 주소로 열 수 있게 하는 것. 예: Vercel, Netlify.
- **빌드 (Build)**: 작성한 코드를 배포할 수 있는 최종 파일로 묶는 과정.
- **빌드 오류 (Build Error)**: 묶는 중에 실패한 것. 로그를 복사해 AI에게 주면 좋음.
- **미리보기 배포 (Preview Deployment)**: 정식 주소 말고 시험용 주소로 먼저 올려 보기.
- **정식 배포 (Production)**: 실제 사용자가 쓰는 최종 주소에 올린 상태.
- **호스팅 (Hosting)**: 웹사이트 파일을 인터넷에 올려 두는 서비스.
- **정적 사이트 (Static Site)**: 서버 처리 없이 파일만으로 보이는 사이트. 무료 배포가 쉬움.
- **도메인 (Domain)**: 웹사이트 주소. 예: eunti.com
- **커스텀 도메인 (Custom Domain)**: vercel.app 같은 기본 주소 대신 내 주소를 연결하기.
- **파비콘 (Favicon)**: 브라우저 탭에 보이는 작은 아이콘.
- **링크 미리보기 (Open Graph Image)**: 카톡·인스타에 링크를 보냈을 때 뜨는 그림과 제목.
- **QR 코드 (QR Code)**: 카메라로 찍으면 주소로 이동하는 네모 무늬. 수업에서 학생 입장에 자주 씀.
- **오픈소스 라이선스 (Open Source License)**: 남이 만든 코드·디자인을 어디까지 써도 되는지 정한 약속. 예: MIT, CC BY.

### 속도
- **로딩 속도 (Page Load Speed)**: 사이트가 열리는 데 걸리는 시간.
- **이미지 최적화 (Image Optimization)**: 화질은 지키며 그림 용량을 줄이기.
- **지연 로딩 (Lazy Loading)**: 화면에 보일 때가 돼서야 그림을 불러오기.
- **용량 (File Size)**: 파일 크기. 클수록 늦게 열림.

## 💬 AI와 일하기

### 기획과 요청
- **프롬프트 (Prompt)**: AI에게 주는 요청 글.
- 🌱 **좋은 프롬프트 4요소**: 누가 쓰는지 · 무엇을 만들지 · 어떤 모양인지 · 무엇은 하지 말지.
- **PRD (제품 요구사항 문서)**: 무엇을, 누구를 위해, 어떤 기능으로 만들지 정리한 기획서.
- **와이어프레임 (Wireframe)**: 색 없이 상자와 선으로만 그린 화면 뼈대.
- **목업 (Mockup)**: 색·글꼴까지 입혀 실제처럼 보이게 만든 정지 화면.
- **프로토타입 (Prototype)**: 눌러 볼 수 있게 연결한 시험용 화면.
- **vs 와이어프레임 vs 목업 vs 프로토타입**
- **레퍼런스 (Reference)**: 원하는 느낌을 보여 주는 참고 이미지나 사이트.
- **디자인 시스템 (Design System)**: 색·글꼴·버튼 모양 등을 정해 둔 규칙 모음.
- **디자인 토큰 (Design Token)**: 디자인 시스템의 값에 붙인 이름. 예: `주요색 = #0095FF`.
- **유저 플로우 (User Flow)**: 사용자가 첫 화면부터 목표까지 거치는 화면 순서.
- **접근성 (Accessibility)**: 장애가 있거나 다양한 환경의 사람도 쓸 수 있게 만드는 것. 큰 글씨, 대비, 키보드 조작, 읽어 주기.
- **대체 텍스트 (Alt Text)**: 그림을 볼 수 없는 사람에게 읽어 주는 그림 설명.
- **예시 주기 (Few-shot Example)**: "이런 식으로"처럼 원하는 결과의 예를 같이 보여 주기.
- **제약 조건 (Constraints)**: "버튼은 3개까지", "글꼴은 Pretendard만"처럼 꼭 지킬 조건을 함께 말하기.
- **체크리스트 확인 (Acceptance Criteria)**: 다 됐는지 판단하는 기준 목록. 마지막에 AI에게 점검시키기.

### 작업 흐름
- **계획 먼저 (Plan First)**: 바로 만들지 말고 계획을 먼저 보여 달라고 해 방향을 맞추기.
- **작게 나눠 요청 (Small Steps)**: 한 번에 다 시키지 말고 화면 하나, 기능 하나씩 요청하기.
- **반복 수정 (Iteration)**: 만들고 보고 고치기를 되풀이하는 방식.
- **스크린샷 피드백 (Screenshot Feedback)**: 화면을 캡처해 "여기 이 부분"을 짚어 고쳐 달라고 하는 방법.
- 🌱 **에러 붙여 넣기 (Paste the Error)**: 오류가 나면 설명하지 말고 에러 메시지를 통째로 붙여 넣기.
- 🌱 **잘 될 때 저장 (Save Working Version)**: 잘 작동할 때마다 파일을 따로 저장하거나 커밋해 두기.
- **되돌리기 (Rollback)**: 문제가 생기면 이전에 잘 되던 버전으로 돌아가기.
- **리팩토링 (Refactoring)**: 겉모습·기능은 그대로 두고 코드만 깔끔하게 정리하기.
- 🌱 **새 대화로 시작 (Fresh Start)**: 대화가 너무 길어져 AI가 헷갈리면 요약과 최신 코드를 들고 새 대화에서 이어가기.

### AI 도구 이해하기
- **채팅형 (Chat Mode)**: AI가 코드를 답으로 주면 내가 복사해서 파일에 붙여 넣는 방식.
- **에이전트형 (Agent Mode)**: AI가 파일을 직접 만들고 고치고 실행까지 하는 방식.
- **vs 채팅형 vs 에이전트형 (Chat vs Agent)**: 채팅형은 코드를 답으로 주고 내가 붙여 넣음, 에이전트형은 AI가 파일을 직접 만들고 고치고 실행함.
- **코딩 에이전트 (Coding Agent)**: 파일 읽기·수정·명령 실행을 스스로 이어서 하는 AI.
- **모델 (Model)**: AI의 두뇌 종류. 빠른 모델, 깊게 생각하는 모델처럼 고를 수 있음.
- **토큰 (Token)**: AI가 글을 읽고 쓰는 단위. 사용량·대화 길이 한도가 토큰으로 계산됨.
- **컨텍스트 (Context)**: AI가 지금 대화에서 기억하고 참고하는 정보의 양.
- **프로젝트 지침 (Project Instructions)**: 매번 말하지 않아도 AI가 항상 지키는 규칙. 예: 하단 저작권 표시.
- **멀티모달 (Multimodal)**: 글뿐 아니라 그림·스크린샷·파일도 함께 이해하는 AI.
- **커넥터 (Connector / MCP)**: AI가 노션·피그마·구글 드라이브 같은 다른 서비스에 연결해 일하게 하는 통로.
- **할루시네이션 (Hallucination)**: AI가 없는 사실이나 기능을 그럴듯하게 지어내는 것.
